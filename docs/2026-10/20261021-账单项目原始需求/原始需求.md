## 一、项目概述

家庭账单系统是一套面向**家庭**的多用户记账与账务管理 Web 系统。核心目标是：

- 支持家庭成员（含家长/管理员与普通成员）分别或协同记账；
- 支持按多种维度（渠道、科目、账目、贷款等）汇总展示账单；
- 支持自定义记账科目、交易渠道（账户）、账目类型等基础信息；
- 支持数据的导入导出；
- 提供"完美账单"（套现指引）功能，辅助生成每日套现需求计划。

---

## 二、总体功能描述

系统总体功能包含：

1. **登录**（含注册）；
2. **记账**（账目明细录入）；
3. **查看汇总账单**（多条件汇总展示）；
4. **家庭账务总分管理**；
5. **自定义记账科目、自定义交易账户（渠道）、自定义账目类型**；
6. **导入导出功能**；
7. **完美账单功能**。

## 三、功能详述

### 3.1 家庭账务总分管理

- 基本账户为**子账户**。
- 多个子账户组成**账户组**；一个账户组内有且仅有一个**管理账户**（即家长/管理员），管理账户可以添加其他子账户为账户组成员。
- 子账户可以管理**自己**的日常账单。
- 账户组的管理账户可以管理**自己以及自己组员**的日常账单。

### 3.2 注册与登录

- 使用系统需先登录；若没有账户则需要注册。
- 暂定使用 **Cookie** 记录登录状态和登录人员 id。

### 3.3 记账

- 向账单系统添加自己的账目明细。
- 记账类型设计详见"四、记账类型设计"。

### 3.4 查看汇总账单

- 账单汇总可以**按不同条件**进行汇总展示（如按渠道、按科目、按账目、按贷款、按年月区间等）。

### 3.5 自定义基础信息

通过自定义以下三类基础信息，用户可以自定义账户科目、账务、收支渠道：

1. **自定义记账科目**；
2. **自定义交易账户（渠道）**；
3. **自定义账目类型**。

### 3.6 导入导出功能

- **导出**：导出用户信息、家庭成员信息、流水信息、账目信息、渠道信息、科目信息等。
- **导入**：导入用户信息、家庭成员信息、流水信息、账目信息、渠道信息、科目信息等。

### 3.7 完美账单功能

- 生成一套**套现指引**，完成**每日套现需求计划**。

### 3.8 家庭 / 用户组 / 配置授权模型（2026-10-25 需求决策补充）

> 本节为项目推进中确认的需求决策（2026-10-25），作为 3.1"家庭账务总分管理"与 7.2 用户表的进一步细化，供后续方案与实现遵循。

**决策要点**

1. 账目类型、交易渠道、记账科目三类基础信息为**家庭级配置**（归属家庭，由家庭管理员维护）。
2. 通过**用户组**控制配置的可见与可用：家庭内可定义多个用户组，一个成员可属于多个组，一个配置可关联多个组；成员只能看到 / 使用其所属组关联的配置。
3. 家庭管理员**天然全可见、全可管**（配置增删改、用户组管理、成员管理）；管理员默认属于"管理员组"，管理员组可有多个管理员。
4. 普通成员：家庭级配置**只读可用**（不能编辑），记账时可引用其可见的配置。
5. **平台超管为预留能力，本期不实现**：家庭管理员为系统内最高权限；仅当系统演变为公网多家庭服务时启用（见下）。
6. **一个用户有且仅属于一个家庭**（`family_id` 单值约束；多家庭场景不作规划）。
7. **新家庭建立时预置种子**：自动创建「管理员组 + 全员组」；账目预置 消费/收入/调账；科目预置 餐饮/交通/日用品等常用项；渠道留空由管理员自行添加。
8. **流水为用户级**：流水由人产生，与 `user_id` 绑定，**无"家庭级流水"概念**；个人流水仅本人可见与维护。
9. **用户组不支持嵌套**：家庭内用户组为扁平结构，不存在组中组。
10. **配置停用即全组不可见**：配置（账目/渠道/科目）停用后，对其关联的所有用户组均不可见、不可用。
11. **加入方式为申请审批**：访客提交加入家庭申请，家庭管理员审批通过后加入并分配用户组。

**模型结构**

```
家庭 Family
 ├─ 用户组 FamilyGroup     （如：全家 / 长辈 / 孩子 / 管理员组）
 ├─ 成员 User              （归属家庭；可归属多个组；isFamilyHead=家庭管理员）
 ├─ 家庭级配置 Trade/Card/Subject（family_id 绑定，管理员维护）
 └─ 配置↔组关联 TradeGroup/CardGroup/SubjectGroup（多对多）
```

**用户角色定位（一个用户可能的角色）**

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 系统状态 | 访客 / 正式成员 | `have_family`：访客未绑定家庭，不可记账；正式成员已归属家庭 |
| 家庭内角色 | 家庭管理员 / 普通成员 | `is_family_head`：管理员天然全可见、全可管，默认属「管理员组」；普通成员仅可见所属组配置 |
| 用户组身份 | 一个或多个用户组 | 决定正式成员的配置可见/可用范围（所属组配置并集） |
| 平台角色（预留） | 普通 / 平台超管 | `system_role`，本期不实现 |

角色组合规则：
- 访客不可能是家庭管理员（管理员身份必须归属家庭）。
- 正式成员加入时由管理员分配用户组（默认「全员组」）。
- 家庭管理员即使未加入某用户组，也天然可见全部配置。

**用户旅程（注册 → 建家/加入 → 正式成员）**

```
注册 → 访客用户（未绑定家庭，have_family=false）
   ├─ 自己建立家庭 → 自动成为家庭管理员（首个管理员，属管理员组）
   │                 自动创建「管理员组+全员组」、预置种子配置
   └─ 加入家庭（申请审批）→ 提交加入申请，管理员审批通过后分配用户组（默认「全员组」）
      ↓
正式成员（have_family=true + family_id）→ 获得家庭内功能权限（记账/查看/使用可见配置）
```

- 访客权限：建立家庭、加入家庭、维护个人资料；**不可记账**（记账需引用家庭级配置，访客无家庭）。
- 加入方式：**申请审批**（访客提交加入申请，家庭管理员审批通过后加入并分配用户组）。

**权限规则**

| 操作 | 家庭管理员 | 普通成员 |
| --- | --- | --- |
| 配置（账目/渠道/科目）增删改 | 全量 | 否 |
| 配置可见 / 记账可用 | 全部配置 | 仅其所属组关联的配置 |
| 用户组 / 成员管理 | 是 | 否 |
| 个人流水 | 本人记账/查看 | 本人记账/查看 |

- 可见性公式：`成员可见配置 = 该成员所属全部组关联配置的并集`。
- 记账时下拉只出现该成员可见的配置。

**表结构草案（V2 增量迁移）**

| 表 | 说明 |
| --- | --- |
| `FamilyGroup` | 用户组：id、family_id（FK Family）、group_name、group_desc、add_date |
| `UserGroup` | 成员↔组（多对多）：user_id、group_id、add_date |
| `TradeGroup` / `CardGroup` / `SubjectGroup` | 配置↔组（多对多）：cfg_id、group_id |
| Trade / Card / Subject | 归属调整为 `family_id`（家庭级），保留创建人 `user_id` 作审计；`User.isFamilyHead` 沿用表示家庭管理员 |

**平台超管（预留能力）**

> 边界声明：家庭管理员为系统内最高权限；**平台超管本期不实现**，仅当系统演变为"一个平台、多家庭注册入驻"的公网服务时启用。

- 角色字段：`user.system_role`（NULL=普通成员 / `super_admin`=平台超管），**独立于** `is_family_head`（家庭管理员），两者互不干扰。
- 超管能力（届时定义）：全量家庭/用户查询、重置成员、停用家庭、数据导出、操作审计日志。
- 入口：独立 `/admin` 后台（与记账主站隔离），而非用户下拉。
- 表：`user.system_role` 字段 + `audit_log`（操作审计日志表）即可，无需新增复杂结构。

**待定项（V2 详设时确认）**

- 旧需求 3.1"管理账户可管理组员日常账单"与"流水为用户级、仅本人可见"存在张力：是否提供管理员代管成员流水的视图，V2 详设时评估。

## 四、记账类型设计

记账类型按**产生流水的条数**划分为 3 类：

### 4.1 一次产生一条流水

记录内容：**发生日期、事情描述、金额、账目类型、账户、科目**。

账目类型一般为：`消费`、`收入`、`调账`。

### 4.2 一次产生两条流水

记录内容：**发生日期、事情描述、from 账户、from 金额、to 账户、to 金额、账目类型、账户、科目**。

账目类型一般为：`还款`、`调账`。

### 4.3 一次产生多条流水

记录内容：**发生日期、事情描述、金额、账目类型、账户、科目**。

账目类型一般为分期贷款相关：如 `消费分期`、`账单分期`、`理财分期`。

## 五、金额约定

- 统一约定：账户**支出**为输入**负值**；账户**收入**为输入**正值**。

## 六、界面与页面需求

系统界面由左侧导航 + 右侧内容区构成。左侧导航菜单结构如下：

```
账户查询
├─ 账户总览
├─ 渠道汇总
├─ 科目汇总
├─ 账目汇总
├─ 贷款汇总
└─ 套现指引（完美账单）
账户修改
├─ 添加明细
└─ 添加账单
设置中心
├─ 个人管理
├─ 家庭管理
├─ 密码修改
├─ 账目设置
├─ 渠道设置
└─ 科目设置
登录 / 退出
```

各主要页面字段需求：

### 6.1 账户总览

- **科目汇总**：第一行从左到右显示科目名称，第二行显示对应科目的**当月消费汇总**。
- **渠道汇总**：第一行从左到右显示渠道的 `账单日 / 还款日、初余额、实时余额、已出账单、本月未还、下月未还、未出账单、余下账单、固定额度、额外额度、剩余固定额度、收入/账/还/用、消费、套现日、还款日`；第二行起依次显示**启用的各类渠道**。
- 提供 `年、月` 及 `起始年月日、结束年月日` 筛选条件与"汇总"操作。

### 6.2 渠道汇总

- 展示启用的各类渠道及其余额、额度、账单/还款等信息（同账户总览中的渠道汇总区），支持年月及起止日期筛选与汇总。

### 6.3 科目汇总

- 第一行显示科目名称，第二行显示对应科目的**当月消费汇总**。
- **汇总按年月进行分行显示**，支持年月及起止日期筛选与汇总。

### 6.4 账目汇总

- 支持按 `年、月、起始年月日、结束年月日` 筛选并汇总展示。

### 6.5 贷款汇总

- 分两个视图：**在贷中** 与 **已结清**。
- 展示字段：`贷款编号、渠道、本金、总利息、期数、开始时间、结束时间、每月还款额、已还本金/百分比、已还利息/百分比、未还本金/百分比、未还利息/百分比、年利率%、月利率%、还款方式、是否可以提前还款、提前还款手续费率、提前还款是否支付剩余手续费`。
- 操作：**提前还款**、**修改贷款基本信息**（已结清视图仅修改贷款基本信息）。

### 6.6 套现指引（完美账单）

- 提供"按卡汇总"、"清空"操作。

### 6.7 添加明细（单次明细）

- 表格列：`序号、交易编号、交易日期、交易说明、交易金额、账目类型、记账科目、资金渠道、备注`。
- 支持三种录入模式切换：**单次明细 / 双次交易 / 贷款·分期**。
- 提供工具栏：`+（新增行）、-（删除行）、向下复制、导入明细、导入、模板下载、提交所选`。

### 6.8 双次交易明细

- 表格列：`序号、交易编号、交易日期、交易说明、from 金额、from 渠道、to 金额、to 渠道、账目类型、记账科目、备注`。
- 示例数据：还款（A201904110001，-25 消费 → 25 工行，还款）、套现（A201904110002，-5500 工行 → 5500 套现）、套现理财成本（A201904110002，-50 套现 → 套现理财成本）。

### 6.9 贷款 / 分期明细

- 表格列：`序号、交易编号、交易说明、渠道、记账开始日期、记账结束日期、金额、期数、年利率、支持提前还款、提前还款手续费率、还款方式、提前还款是否支付剩余手续费率、备注`。
- 示例：C201904110001，账单分期，工行，19-4-11 ~ 21-4-11，10000，12期，16%，支持提前还款，手续费 0.5%，等额本金，是。

### 6.10 添加账单

- 表格列：`序号、账单编号、渠道、账单金额、账单日期、最后还款日`。

### 6.11 个人管理

- 展示字段：`用户 id、用户昵称、用户头像、电话号码、邮箱、加入家庭编号、家庭管理员、账号启用`，提供"修改信息"操作。
- 修改页提供"放弃修改"、"提交修改"。

### 6.12 家庭管理

- 展示：`家庭昵称（家庭 id）`、`添加成员`、`成员顺序号、成员 id、成员昵称、成员备注`，成员行提供"删除"操作。

### 6.13 密码修改

- 输入：`原密码、新密码、确认密码`，提供"确认修改"。

### 6.14 账目设置

- 表格列：`账目顺序号、名称、描述`，行操作：`删除、修改`。

### 6.15 渠道设置

- 表格列：`渠道顺序号、渠道名称、渠道描述、类型、卡号、固定额度、初始余额、账单日、还款日、是否激活、是否汇总`，行操作：`删除、修改`。

### 6.16 科目设置

- 表格列：`科目顺序号、科目名称、科目描述、是否激活、是否汇总`，行操作：`删除、修改`。

### 6.17 记账录入说明（账目类型过程）

- 记账录入项：`账目类型、日期、from 账户、from 金额、to 账户、to 金额、分期类型、备注`。
- 过程划分：**一次性**（普通消费）、**双向性**（调账、还款）、**多次性**（分期）。
