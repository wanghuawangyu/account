## 2. 开发目标与范围

### 2.1 目标

在 `F:\project\account` 从零构建一个**单一可执行服务程序**：内置 Web 服务 + REST API + 前端页面 + SQLite 数据库，**前端随编译一起打包进二进制**，二进制可直接运行，同时可在 Windows 电脑与安卓手机上运行。

### 2.2 功能范围（对应需求章节）

| 编号 | 功能 | 需求章节 | 说明 |
| --- | --- | --- | --- |
| F1 | 登录 / 注册 / 退出 / 改密 | 3.2 | 会话认证（**V2**，V1 免登录） |
| F2 | 家庭账务总分管理 | 3.1 | 家庭 + 家长/成员（**V2**，V1 单用户） |
| F3 | 记账（单次 / 双次 / 分期） | 3.3、四 | 三类流水 |
| F4 | 汇总查询（渠道/科目/账目/贷款/总览） | 3.4、六 | 多条件汇总 |
| F5 | 自定义基础信息（账目/渠道/科目） | 3.5、6.14-6.16 | CRUD |
| F6 | 导入导出 | 3.6 | 六类信息 |
| F7 | 完美账单（套现指引） | 3.7、6.6 | 每日套现计划 |

### 2.3 运行形态

| 平台 | 交付物 | 运行方式 |
| --- | --- | --- |
| Windows（本期重点） | 单个 **.exe**（静态链接，不依赖运行时 DLL） | 双击运行 → 启动本地 HTTP 服务 → 自动打开默认浏览器访问 `http://127.0.0.1:<port>` |
| Android（服务端） | Termux 中运行的 Rust server（`aarch64-linux-android` ELF） | Termux 后台长期运行服务 → 走**内网穿透**公开到外网 → 外网多端浏览器访问 |
| Android（客户端，后续规划） | 基于 WebView 封装的 App | 封装后前端功能与电脑端一致，需按手机端单独适配（归后续需求规划） |

### 2.4 版本划分（V1 / V2）

本项目以**单用户工具软件**定位，分两阶段交付：

| 版本 | 定位 | 范围 |
| --- | --- | --- |
| **V1（本期）** | 单用户、免登录，聚焦核心记账（先交付电脑端浏览器可用） | 记账（单次/双次/分期）、汇总、账单、贷款、完美账单、导入导出、基础信息；开箱即用，数据归属内置"默认用户" |
| **V2（后期扩展）** | 多用户、家庭协同 | 注册/登录/退出/改密、用户管理、家庭管理（家长/成员、账户组权限） |

### 2.5 边界与暂不纳入（V1 之外）

- 本期以**电脑端浏览器**为主交付；Android 端通过 **Termux 运行服务 + 内网穿透公开**，供外网浏览器访问。
- **Android WebView 封装 App**（前端功能与电脑端一致、按手机端单独适配）作为**后续需求规划**，本期不做。
- **V1 不做登录/用户/家庭管理**（属 V2）；数据模型仍保留 user/family 表，供 V2 平滑启用。
- 不做原生 App 业务逻辑、不做支付、短信、第三方登录集成（预留扩展点）。

## 3. 总体技术方案

### 3.1 技术栈选型（已确认方向）

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | **Rust**（edition 2021，`rust-toolchain` 锁定版本） | 内存安全、静态编译、跨平台 |
| Web 框架 | **axum** + **tokio** | 异步、路由/中间件/提取器完善，生态成熟 |
| 数据库 | **SQLite**（单文件、免服务） | 嵌入式，随二进制分发，数据文件本地化 |
| 异步数据库访问 | **sqlx**（`sqlx::sqlite`，连接池 + 迁移） | 与 axum 同 async 生态；可选 `rusqlite`（同步、更简） |
| 前端嵌入 | **rust-embed**（编译期把静态资源内嵌进二进制） | 满足"前端随编译打包进二进制" |
| 认证（V2） | **argon2**（密码散列）+ **JWT/签名会话**（`jsonwebtoken`） | V1 免登录（单用户）；V2 启用登录与鉴权 |
| 序列化 | **serde / serde_json** | JSON API |
| 日期 | **time**（或 chrono） | 统一 ISO-8601 文本存储 |
| 导入导出 | **csv** crate + **rust_xlsxwriter**（或 openpyxl 替代→ 用 `rust_xlsxwriter`） | CSV 与 XLSX 模板 |
| 错误处理 | anyhow / thiserror | 统一错误映射为 JSON |
| HTTP 中间件 | tower-http（CORS、压缩、日志） | — |

### 3.2 架构（单二进制）

```
单一可执行文件
├── Rust 服务（axum）
│    ├── REST API  /api/*
│    ├── 静态前端  /（rust-embed 内嵌资源）
│    └── SQLite 数据文件（data.db，本地磁盘）
```

### 3.3 跨平台编译与静态链接

**编译目标**

| 平台 | Target | 说明 |
| --- | --- | --- |
| Windows（本期重点） | `x86_64-pc-windows-msvc`（或 `-gnu`） | `cargo build --release` |
| Android（服务端） | `aarch64-linux-android` | 交叉编译 ELF 可执行，在 Termux 中运行（也可在 Termux 内直接用 cargo 编译） |
| Linux（可选，CI/静态验证） | `x86_64-unknown-linux-musl` | 纯静态 |

**静态链接要点**
- Windows：`.cargo/config.toml` 中对目标设置 `rustflags = ["-C","target-feature=+crt-static"]`（MSVC 静态 CRT）或用 GNU 工具链，产出**不依赖运行时 DLL** 的独立 `.exe`。
- Android：Rust 三方依赖全部静态链接进产物；产物为 ELF 可执行，链接 Termux/bionic libc（Android 自带，无需额外分发）。
- 所有 Rust crate 依赖静态编译进单一产物，无外部动态库。

**Android 运行形态（已决策）**
- **本期（服务端）**：在 **Termux** 中长期运行 Rust server（ELF，后台驻留），通过**内网穿透**（frp / natapp / cloudflared 等）公开到外网，外网多端浏览器访问。
- **后续规划（客户端）**：基于 **WebView 封装 App** 访问服务，前端功能与电脑端一致，需按手机端单独适配（作为后续需求规划，本期不做）。

## 4. 数据库设计（SQLite）

### 4.1 模型总览（9 张表）

```
Family (家庭/账户组)
  └─< User (用户/子账户) —— isFamilyHead=家长(管理账户)
        ├─< Trade  (账目类型)   Card (交易渠道/卡片)   Subject (记账科目)
        └─< Detail (流水) ──→ Trade / Card / Subject
        └─< Bill   (每月账单) ──→ Card
        └─< Installment (分期贷款) ──→ Card
MerchantType (套现商户渠道) —— 新增
```

### 4.2 表定义（SQLite 落地）

> **金额一律用 INTEGER 存"分"（i64）**，避免浮点误差；接口层换算为元（两位小数展示）。日期统一 `TEXT` ISO-8601（`YYYY-MM-DD`），时间统一 `TEXT` ISO-8601（`YYYY-MM-DDTHH:MM:SS`）。每张表含 `id INTEGER PRIMARY KEY AUTOINCREMENT`；外键建索引；连接级开启 `PRAGMA foreign_keys=ON`。

| 表 | 主键 | 关键字段（类型） | 外键/说明 |
| --- | --- | --- | --- |
| **family** | id | family_name TEXT, created_at TEXT | — |
| **user** | id | user_name TEXT, user_tel TEXT(唯一), user_email TEXT(唯一), password_hash TEXT, have_family INTEGER(0/1), is_family_head INTEGER(0/1), is_active INTEGER(0/1), family_id INTEGER NULL, family_mark_name TEXT, family_order_number INTEGER, created_at TEXT | →family |
| **trade** | id | trade_name TEXT, trade_desc TEXT, trade_order_number INTEGER, trade_order_mark TEXT, user_id INTEGER, created_at TEXT | →user |
| **card** | id | card_name TEXT, card_desc TEXT, card_type TEXT, card_number TEXT, card_fixed_credits INTEGER(分), card_start_amount INTEGER(分), card_bill_day TEXT, card_repayment_day TEXT, is_card_active INTEGER, is_card_count INTEGER, card_order_number INTEGER, card_remark TEXT, user_id INTEGER, created_at TEXT | →user |
| **subject** | id | subject_name TEXT, subject_desc TEXT, is_subject_active INTEGER, is_subject_count INTEGER, subject_order_number INTEGER, user_id INTEGER, created_at TEXT | →user |
| **detail** | id | detail_date TEXT, trade_date TEXT, trade_number INTEGER, detail_desc TEXT, detail_amount INTEGER(分，支出为负/收入为正), detail_no INTEGER, installment INTEGER(0/1), is_card_other_credits INTEGER, is_detail_active INTEGER, user_id INTEGER, trade_id INTEGER, card_id INTEGER, subject_id INTEGER | →user/trade/card/subject |
| **bill** | id | bill_date TEXT, bill_amount INTEGER(分), bill_repayment_date TEXT, is_repayment INTEGER, user_id INTEGER, card_id INTEGER, created_at TEXT | →user/card |
| **installment** | id | installment_number INTEGER, installment_desc TEXT, installment_date TEXT, start_date TEXT, end_date TEXT, month_count INTEGER(默认12), is_allow_prepayment INTEGER, prepayment_rate INTEGER(万分比或分), repayment_method TEXT, interest_rate_year INTEGER, amount INTEGER(分), is_pay_next_interest INTEGER, user_id INTEGER, card_id INTEGER, created_at TEXT | →user/card |
| **merchant_type**（新增） | id | merchant_type_name TEXT, is_online INTEGER, online_rate INTEGER, is_outline INTEGER, outline_rate INTEGER, order_number INTEGER, created_at TEXT | 支撑 F7 |

### 4.3 迁移方案

- 采用 **sqlx migrate**（`migrations/*.sql`，`PRAGMA user_version` 记账），服务启动时自动执行未应用迁移。
- 首个迁移建全部 9 张表 + 索引 + 外键；后续字段变更走增量迁移，保证已有数据文件平滑升级。

### 4.4 与需求差异的处理决策

| 差异（见需求九） | 设计决策 |
| --- | --- |
| 套现渠道表缺失 | 新增 `merchant_type` 表，支撑 F7。 |
| 家庭总分管理的"账户组/管理账户" | 以 `family`=账户组、`user.is_family_head`=管理账户、`family_id` 归属实现；权限规则见 6.4。 |
| 金额精度 | SQLite 无 DECIMAL，统一 **INTEGER 分（i64）**；支出为负、收入为正（见 6.2）。 |
| 登录/注册 | 新增 `password_hash`（argon2）；登录用手机号/邮箱 + 密码；签发签名会话令牌（见 6.7）。 |
| 导入导出 | 定义统一模板与字段映射（见 6.6）。 |

## 6. 核心业务逻辑设计

### 6.1 记账类型处理

| 类型 | 流水条数 | 逻辑 |
| --- | --- | --- |
| 单次（消费/收入/调账） | 1 | 写一条 detail |
| 双次（还款/调账） | 2 | 生成 from 账户(负) 与 to 账户(正) 两条 detail，同一 trade_number |
| 多次（消费分期/账单分期/理财分期） | ≥2 | 生成一笔 installment + 按期生成多条 detail |

> 双次与分期在**同一 SQLite 事务**内完成多条写入（`BEGIN IMMEDIATE`…`COMMIT`），保证一致性。

### 6.2 金额约定与校验

- 支出（from/消费）为**负值**；收入（to/收入）为**正值**。
- 金额统一以 **INTEGER 分**存储与计算；接口层换算为元（保留两位）。禁止 f64 参与金额计算。
- 双次交易要求 from 与 to 金额**绝对值相等**（还款/调账），后端强校验。

### 6.3 汇总逻辑

- 流水聚合：SQL 分组 + 时间区间（年/月/起止）过滤，按渠道/科目/账目/贷款维度。
- 渠道余额：`初始余额 + Σ收入 - Σ支出` 得实时余额；按账单日/还款日划分"已出账单、本月未还、下月未还、未出账单"。
- 科目汇总：按年月份行显示各科目当月消费合计。
- 贷款汇总：按结清状态分"在贷中/已结清"，含本金/利息/已还/未还及百分比、年/月利率、还款方式、提前还款信息。

### 6.4 家庭总分管理权限（V2）

- **V1（单用户）**：无权限矩阵，所有数据归属默认用户，接口不做归属鉴权，开箱即用。
- **V2（多用户）**：
  - `is_active=0` 的用户不可登录。
  - **子账户**：仅能读写**自己**名下的账目/渠道/科目/流水/账单/贷款。
  - **家长（is_family_head=1）**：额外可读写**同家庭（family_id 相同）成员**名下数据，并可添加/移除/修改成员。
  - 所有写接口做数据归属校验（owner/family_id == 当前用户，或当前用户为该家庭家长）；权限校验作为 axum 中间件统一处理。

### 6.5 完美账单 / 套现指引算法

- 输入：激活渠道（is_card_active=1）、merchant_type（线上/线下及费率）。
- 处理：按卡统计当月已消费与待还额度，结合各商户类型线上/线下比率与费率，生成**每日套现需求计划**（哪张卡、经哪个商户类型、套现多少、对应还款安排）。
- 输出：`/api/cashout/plan` 返回按卡汇总计划；页面提供"按卡汇总"与"清空"。
- 说明：算法参数以 merchant_type 表配置为准，规则需与用户确认（见 10.3）。

### 6.6 导入导出

- 模板：CSV（UTF-8 with BOM）与 XLSX 两种，表头与字段英文名一一对应。
- 字段映射：六类资源各维护一张"模板列 ↔ 模型字段"映射表。
- 校验：导入逐行校验（必填、类型、金额精度、外键存在性），返回错误行号与原因；支持部分成功。
- 导出范围：用户、家庭成员、流水、账目、渠道、科目。

### 6.7 认证与会话（Rust 侧，V2）

- **V1** 免登录：服务启动即用，无认证接口；数据归属以默认用户（id=1）兜底。
- **V2** 启用登录：
  - 密码 argon2 散列存储于 `password_hash`。
  - 登录校验通过后签发**签名会话令牌**（JWT，含 user_id/家庭/家长标志），客户端以 `Authorization: Bearer <token>` 或 HTTP-only Cookie 携带。
  - 鉴权中间件解析校验令牌、注入当前用户；未登录访问受保护接口返回 401。
  - 会话过期、改密后令牌失效策略在 V2 实现时明确。

## 7. 前端规划（嵌入式）

- 前端为**静态 SPA / 多页面静态资源**，构建产物（HTML/CSS/JS）经 `rust-embed` **编译期嵌入二进制**；axum 以 `/` 提供页面、`/api/*` 提供数据，无外部 CDN 依赖（保证离线可用）。
- **开发期 mock 先行**：前端以静态数据 + mockFetch 先行走通基本展示（里程碑 M4），展示确认后再接真实接口；构建期才将资源嵌入二进制。
- **V1 免登录直达**：默认入口即记账首页/账户总览，无登录页拦截。
- 统一布局：左侧导航（需求 6 节菜单结构）+ 右侧内容区，`layout` 复用。
- 样式：Bootstrap 5（本地内置）或轻量自写 CSS；汇总页卡片/分区展示。
- 交互：记账页三 Tab（单次/双次/分期）；工具栏 `+ - 向下复制 导入 模板下载 提交所选`；设置页行内编辑。
- 校验：前端即时反馈，后端为最终权威校验（前后端字段保持一致，见 10.4）。
- **平台适配**：界面需兼顾 Windows 桌面宽屏与安卓手机竖屏（响应式断点）。

## 8. 测试规划（P0–P3 分级）

> **开发流程**：先产出**集成测试文档**并实现基础测试用例自动化（里程碑 M6），后端实现后按测试文档完成自动化用例、基础用例全跑通（里程碑 M9）方可视为第一版可用。
> 测试工具：`cargo test`（单元 + 集成）；数据库测试用**内存 SQLite 或临时文件**；金额/汇总类用确定性样例断言，禁止仅看"运行成功"。

| 级别 | 范围 | 要点 |
| --- | --- | --- |
| **P0** | 金额符号与精度（INTEGER 分）、双次/分期事务一致性、核心 CRUD 不丢数据（V1）；登录/注册/退出与数据归属权限（V2） | 安全、数据正确性 |
| **P1** | 记账三类、四类汇总、渠道余额、账单、贷款与提前还款、导入导出主流程 | 核心业务 |
| **P2** | 家庭管理（增删成员）、各设置页 CRUD、模板下载、筛选/分页 | 常规功能 |
| **P3** | 前端校验提示、空态/边界（金额 0、极值、日期区间颠倒）、响应式、性能（万级流水分页） | 边缘与体验 |

**双端冒烟**：Windows 编译出的 `.exe` 双击自启+自动开浏览器（本期重点）；Android Termux 运行服务并经内网穿透后，外网浏览器可访问，均验证**免登录一笔记账闭环**。

## 9. 开发里程碑与排期（建议）

### 9.1 开发方法（流程基线）

本项目按"**界面/原型先行、文档驱动、测试先行、迭代式开发**"的方法推进，流程如下：

1. **理清需求**：整理并冻结需求清单与范围（已基于原始需求文档建立基线）。
2. **描述界面功能，生成界面模拟图**：明确各页面功能，产出界面模拟图/线框图。
3. **生成前端需要的接口清单和界面清单**：输出前端所需接口清单与界面清单。
4. **生成前端 html 文件和静态数据，使用 mockFetch 基于静态数据先走通 html 基本展示，继续修改需求和界面**：前端原型以静态数据驱动先行展示，据此迭代需求与界面。
5. **生成 use-case**：编写用例文档。
6. **生成集成测试文档并实现基础测试用例自动化**：先定测试文档与基础自动化用例。
7. **生成后端设计文件和 db 表定义，人工审核检视直到符合预期**：后端设计 + SQLite 表定义，经人工审核冻结。
8. **按照前后端文档，开发第一版程序，能运行起来**。
9. **按照测试文档，完成自动化测试用例开发，要求基础用例都跑过**，产出第一版可运行 App。
10. **迭代功能和小型 bug 修复**，迭代时及时补充和完善自动化测试用例。

## 10. 风险与待确认事项

| 编号 | 事项 | 影响 | 建议 |
| --- | --- | --- | --- |
| 10.1 | **内网穿透工具与公开方式**（frp / natapp / cloudflared 等） | 决定 Android 服务对外公开的地址、稳定性与费用 | 需确认工具与域名/公网地址；隧道应带访问凭据/密码；长期稳定公开方案待选 |
| 10.2 | **公网暴露安全（V1 免登录）** | V1 无登录鉴权，内网穿透公网暴露存在数据被他人访问风险 | 隧道加访问保护（凭据/密码/白名单）；正式对外建议先启用 V2 登录 |
| 10.3 | 套现指引（完美账单）算法规则 | F7 核心，规则影响结果正确性 | 需用户确认费率/比率口径与每日计划生成规则 |
| 10.4 | 前端方案（纯静态多页 vs SPA 框架） | 影响开发节奏与打包 | 建议轻量静态多页（Bootstrap），不引重型框架；需确认 |
| 10.5 | **单用户→多用户迁移路径**（V1→V2） | V1 数据归属默认用户，V2 引入登录后需迁移归属 | V1 即建好 user/family 表、默认用户兜底；V2 做数据归属迁移 |
| 10.6 | 认证与会话安全（V2 启用） | 密码存储、令牌过期、改密失效 | argon2 散列；JWT 过期时间；改密后旧令牌失效策略在 V2 明确 |
| 10.7 | 金额精度 | 汇总准确性 | 全局 INTEGER 分，禁止 f64；作为不可变约定 |
| 10.8 | SQLite 数据安全/备份 | 单文件易损坏、误删 | 定期备份 data.db、WAL 模式、迁移保护 |
| 10.9 | 端口与启动体验 | 端口占用、浏览器/WebView 兼容 | 默认 127.0.0.1 端口可配置；启动检测端口占用并提示 |

## 11. 验收标准

1. **V1 免登录开箱即用**：启动即进入记账功能，无需注册登录；**电脑端浏览器功能完整可用**（本期重点）。
2. 记账三类、四类汇总、账单、贷款、套现指引、导入导出主流程通过 P0/P1 用例。
3. **Windows 单个 .exe** 静态运行、自动开浏览器；**Android**：Termux 中运行服务并经**内网穿透**公开，外网多端浏览器可访问。
4. 9 张表落地（SQLite），迁移自动执行、数据文件可升级；user/family 表为 V2 预留。
5. 金额统一 INTEGER 分、双次/分期事务一致、无脏数据。
6. 前后端字段一致、API 与前端页面一一对应、文档与代码一致。
7. V2（多用户）接入时，登录/用户/家庭管理与既有数据平滑迁移。
8. Android WebView 封装 App（前端功能与电脑端一致、按手机端适配）作为后续需求规划，本期不纳入验收。
